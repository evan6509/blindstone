# Configuration and administration

Normal startup runs the private alpha after mandatory hooks and configuration validate. The isolated `-Dblindstone.development=true` test mode keeps player admission denied. Graphical-client acceptance and SMP capacity are separate from configuration readiness.

When the runtime initializes, it creates `config/blindstone.json` if absent. Defaults are written through a temporary file and an atomic move. The example below is the file generated by `ConfigCodec.encode(BlindstoneConfig.defaults())` in the GameTest server:

```json
{
  "schemaVersion": 1,
  "dimensions": [
    "minecraft:overworld"
  ],
  "protectedMaxY": 64,
  "concealAir": true,
  "protectNonPlayerEntities": true,
  "soundPolicy": "preserve_audible",
  "replacements": {
    "aboveZero": "minecraft:stone",
    "belowZero": "minecraft:deepslate"
  },
  "revealRangeBlocks": 16,
  "refreshIntervalTicks": 1,
  "movementSafetyRadiusBlocks": 0.0625,
  "budgets": {
    "maxViewers": 128,
    "maxTrackedChunksPerViewer": 1024,
    "maxGlobalTrackedChunks": 8192,
    "maxQueuedChunksPerViewer": 128,
    "maxGlobalQueuedChunks": 8192,
    "maxSnapshotBlocksPerJob": 262144,
    "maxGeometryChecksPerTickPerViewer": 65536,
    "maxGeometryChecksPerTickGlobal": 262144,
    "maxWorkNanosPerTick": 15000000,
    "maxMaskBytes": 67108864,
    "movementDeliveryDeadlineTicks": 20
  }
}
```

## Policy settings

Every field shown above is required. Unknown, duplicate, missing, mistyped, fractional integer, and unsupported values are rejected. Comments and trailing JSON documents are invalid. The file is limited to 64 KiB. There is no `enabled`, bypass, automatic fallback, or custom replacement-block setting in this schema.

| Field | Accepted behavior |
| --- | --- |
| `schemaVersion` | Exactly `1`. |
| `dimensions` | Exactly `["minecraft:overworld"]`; Nether, End, unknown IDs, duplicates, and empty lists are rejected. |
| `protectedMaxY` | Exclusive upper bound, a multiple of 16 within `[-2032,2048]`. It must exceed the actual world minimum, fit within the actual world height, and protect at most 1024 vertical blocks. |
| `concealAir` | Must remain `true`. Hidden air and fluids use replacement terrain too. |
| `protectNonPlayerEntities` | Must remain `true`. This required policy does not establish complete entity support; see the coverage report. |
| `soundPolicy` | Exactly `preserve_audible`. Ordinary delivered sounds remain discovery clues; entity-attached sounds may become positional sounds. |
| `replacements` | Exactly stone at Y≥0 and deepslate below Y=0. Other block IDs, including otherwise opaque blocks, are currently rejected. |
| `revealRangeBlocks` | Integer 4–16; default 16. Range selects geometric candidates and never authorizes a through-wall distance bubble. |
| `refreshIntervalTicks` | Integer 1–20; default 1. Dirty work can run sooner. Larger intervals can exceed the fixed accepted-movement segment limit. |
| `movementSafetyRadiusBlocks` | Exactly `0.0625`: the accepted body and swept movement path are expanded by 1/16 block. |

The lower bound always comes from the world's actual minimum height. For a world with minimum Y=-64, defaults protect `minecraft:overworld Y[-64,64)`; Y=64 is outside protection. `/blindstone status` and reports show the effective bounds. Replacement choices are independent of real terrain, ores, caves, and player construction.

The movement exception may disclose a neighboring cell when the accepted body nearly touches its wall. It never expands under load. Accepted player and root-vehicle bodies are bounded to 4×4×4 blocks, with a fixed 1/16-block margin. A normal runtime path is limited to 16 blocks between evaluations. Its straight swept body corridor connects the accepted endpoints; it does not reconstruct intermediate axis-resolved bends. At most 8192 safety cells are scanned; larger bodies, paths or unavailable destination chunks fail closed. Explicit lifecycle resets rebase the previous body instead of enlarging the envelope.

## Budgets and their limits

These are private-alpha limits, not measured SMP capacity. Lowering a limit can make delivery unavailable; the runtime does not silently increase it or send real hidden data instead.

| Budget | Default | Validation and runtime meaning |
| --- | ---: | --- |
| `maxViewers` | 128 | 1–1024 tracked viewer sessions globally. |
| `maxTrackedChunksPerViewer` | 1024 | 1–4096 chunk subscriptions per viewer. |
| `maxGlobalTrackedChunks` | 8192 | 1–65536 subscriptions across viewers. |
| `maxQueuedChunksPerViewer` | 128 | 1 through the per-viewer tracked-chunk limit; bounds pending work for that viewer. |
| `maxGlobalQueuedChunks` | 8192 | 1 through the global tracked-chunk limit; bounds pending viewer pipelines/reveal plans. |
| `maxSnapshotBlocksPerJob` | 262144 | 4096–2097152 cells; required snapshot size is checked before capture. Geometry has a tighter fixed maximum of 42875 cells. |
| `maxGeometryChecksPerTickPerViewer` | 65536 | 1–1048576 voxel/shape checks per viewer per tick, shared with bounded entity sight checks. |
| `maxGeometryChecksPerTickGlobal` | 262144 | At least the per-viewer limit and at most 16777216; shared globally, including tracker scheduling slots. |
| `maxWorkNanosPerTick` | 15000000 | 100000–50000000 ns; the default is a 15 ms measured-work guard. |
| `maxMaskBytes` | 67108864 | 1024–1073741824 bytes; bounds charged visibility-mask payload, not total JVM heap. |
| `movementDeliveryDeadlineTicks` | 20 | 1–100, at least the refresh interval; missed movement-safe delivery deadlines disconnect the affected viewer. |

One resumable sight job is retained per viewer. Camera, ray, candidate, and shape cursors survive work exhaustion; a later step resumes rather than rescanning the same near blocks indefinitely. Fresh body safety is evaluated independently. Viewer scheduling rotates, and chunk/geometry/lifecycle changes invalidate affected work. Visibility plans and incremental light jobs keep separate bounded progress. Frozen plans coalesce newer desired knowledge until matching light is ready; batch publication preserves callback/order semantics.

At range 8, a full visibility snapshot contains at most 6859 cells; at range 16, at most 42875. A smaller configured snapshot budget can therefore reject a range that is otherwise syntactically valid. Temporary snapshots, geometry objects, entity IDs, and collection overhead are separate from `maxMaskBytes`. Mask accounting reserves 1024 bytes per protected section per tracked chunk for delivered and pending bit payloads; ordinary default bounds have eight protected sections.

Light reconstruction has a fixed shared **128 MiB** job/cache cap, with at most **16 active jobs** and **128 ready light entries** per viewer. Its fixed-capacity queues, cooperative work slices, generation keys and 15-block halo bound memory and prevent stale publication. These allocations are separate from `maxMaskBytes`. Capacity exhaustion queues delivery or disconnects when safe movement cannot be maintained; it never grants visibility.

The runtime also caps announced entity IDs at **16384 per viewer**. This fixed limit is not a configuration field. Saturation fails closed.

The **15 ms guard is not a hard deadline inside capture or one evaluator step**. Work checks between stages and before reveal packets stop subsequent work, but an individual bounded operation can overshoot before returning. Aggregate timings and counters describe instrumented work; they do not prove whole-server tick cost, reveal latency, total memory, or throughput. Client gameplay and representative SMP benchmarks remain required.

## Administration and reload

Commands require vanilla gamemaster command permission. Operator status grants no viewing bypass.

| Command | Current behavior |
| --- | --- |
| `/blindstone status` | Activation/admission state, versions, effective dimension/bounds, viewers, tracked chunks, backlog, and aggregate failure count. |
| `/blindstone verify` | Separates hook loading, observed packets, rewritten/dropped packets, enforcement, automated-test evidence, and live-test evidence by path. Unobserved or untested paths remain labeled accordingly. |
| `/blindstone inspect <player>` | Restricted viewer summary: tracked chunks, queued plans, visibility-job progress, announced entity count, and bypass state. |
| `/blindstone reload` | Validates the entire file first; publishes only after runtime reconciliation accepts it. Changing vertical protection bounds requires no active viewers; compatible changes invalidate and refresh existing work. |
| `/blindstone report` | Atomically writes local sanitized diagnostics to `config/blindstone-reports/latest.json`. |

For reload, edit the complete file and run `/blindstone reload`. A rejected candidate retains the previous effective configuration and generation. Changes that cannot be reconciled with active viewer state are rejected; disconnect viewers before changing protection bounds. Reload does not re-enable an explicitly disabled runtime.

`blindstone disable` is visible only to the actual server console. It prints the disclosure that real world delivery will resume. `blindstone disable confirm` disables filtering and disconnects tracked viewers; reconnecting clients then receive the real world. Server restart re-enables the normal protection policy. Players, command blocks and RCON are excluded from this console-only command by source identity, not merely operator permission.

Reports contain configuration/bounds, versions, aggregate timings/counters, typed failure counts, and coverage evidence. They omit player identities, world coordinates other than configured vertical bounds, seeds, raw world data, file paths, and arbitrary exception messages. They stay local; there is no telemetry or automatic updater.

Invalid configuration, overload, missing hooks or filtering failures never automatically switch protected-world delivery to unfiltered data. The explicit console command is the only runtime disable path. There is no telemetry or automatic updater.
