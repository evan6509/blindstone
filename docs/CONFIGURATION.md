# Configuration and development commands

Blindstone remains a closed-admission development prototype. Normal startup refuses activation. An isolated developer server can use `-Dblindstone.development=true`, but player admission remains denied. Configuration and passing automated tests do not enable production protection.

When the development runtime initializes, it creates `config/blindstone.json` if absent. Defaults are written through a temporary file and an atomic move. The example below is the file generated by `ConfigCodec.encode(BlindstoneConfig.defaults())` in the GameTest server:

```json
{
  "schemaVersion": 1,
  "dimensions": [
    "minecraft:overworld"
  ],
  "protectedMaxY": 64,
  "concealAir": true,
  "protectNonPlayerEntities": true,
  "soundPolicy": "preserve_audible",
  "replacements": {
    "aboveZero": "minecraft:stone",
    "belowZero": "minecraft:deepslate"
  },
  "revealRangeBlocks": 8,
  "refreshIntervalTicks": 1,
  "movementSafetyRadiusBlocks": 0.0625,
  "budgets": {
    "maxViewers": 128,
    "maxTrackedChunksPerViewer": 1024,
    "maxGlobalTrackedChunks": 8192,
    "maxQueuedChunksPerViewer": 128,
    "maxGlobalQueuedChunks": 8192,
    "maxSnapshotBlocksPerJob": 262144,
    "maxGeometryChecksPerTickPerViewer": 8192,
    "maxGeometryChecksPerTickGlobal": 262144,
    "maxWorkNanosPerTick": 5000000,
    "maxMaskBytes": 67108864,
    "movementDeliveryDeadlineTicks": 20
  }
}
```

## Policy settings

Every field shown above is required. Unknown, duplicate, missing, mistyped, fractional integer, and unsupported values are rejected. Comments and trailing JSON documents are invalid. The file is limited to 64 KiB. There is no `enabled`, bypass, automatic fallback, or custom replacement-block setting in this schema.

| Field | Accepted behavior |
| --- | --- |
| `schemaVersion` | Exactly `1`. |
| `dimensions` | Exactly `["minecraft:overworld"]`; Nether, End, unknown IDs, duplicates, and empty lists are rejected. |
| `protectedMaxY` | Exclusive upper bound, a multiple of 16 within `[-2032,2048]`. It must exceed the actual world minimum, fit within the actual world height, and protect at most 1024 vertical blocks. |
| `concealAir` | Must remain `true`. Hidden air and fluids use replacement terrain too. |
| `protectNonPlayerEntities` | Must remain `true`. This required policy does not establish complete entity support; see the coverage report. |
| `soundPolicy` | Exactly `preserve_audible`. Ordinary delivered sounds remain discovery clues; entity-attached sounds may become positional sounds. |
| `replacements` | Exactly stone at Y≥0 and deepslate below Y=0. Other block IDs, including otherwise opaque blocks, are currently rejected. |
| `revealRangeBlocks` | Integer 4–16; default 8. Range selects geometric candidates and never authorizes a through-wall distance bubble. |
| `refreshIntervalTicks` | Integer 1–20; default 1. Dirty work can run sooner. Larger intervals can exceed the fixed accepted-movement segment limit. |
| `movementSafetyRadiusBlocks` | Exactly `0.0625`: the accepted body and swept movement path are expanded by 1/16 block. |

The lower bound always comes from the world's actual minimum height. For a world with minimum Y=-64, defaults protect `minecraft:overworld Y[-64,64)`; Y=64 is outside protection. `/blindstone status` and reports show the effective bounds. Replacement choices are independent of real terrain, ores, caves, and player construction.

The movement exception may disclose a neighboring cell when the accepted body nearly touches its wall. It never expands under load. The evaluator bounds body size to 1×2×1 blocks, safety cells to 96, and each accepted movement segment to 1.5 blocks between evaluations. Mounted movement has no validated vehicle-body envelope and fails closed. Longer movement segments also fail closed; explicit lifecycle resets rebase the previous body instead of enlarging the envelope.

## Budgets and their limits

These are prototype limits, not measured SMP capacity. Lowering a limit can make delivery unavailable; the runtime does not silently increase it or send real hidden data instead.

| Budget | Default | Validation and runtime meaning |
| --- | ---: | --- |
| `maxViewers` | 128 | 1–1024 tracked viewer sessions globally. |
| `maxTrackedChunksPerViewer` | 1024 | 1–4096 chunk subscriptions per viewer. |
| `maxGlobalTrackedChunks` | 8192 | 1–65536 subscriptions across viewers. |
| `maxQueuedChunksPerViewer` | 128 | 1 through the per-viewer tracked-chunk limit; bounds pending work for that viewer. |
| `maxGlobalQueuedChunks` | 8192 | 1 through the global tracked-chunk limit; bounds pending viewer pipelines/reveal plans. |
| `maxSnapshotBlocksPerJob` | 262144 | 4096–2097152 cells; required snapshot size is checked before capture. Geometry has a tighter fixed maximum of 42875 cells. |
| `maxGeometryChecksPerTickPerViewer` | 8192 | 1–1048576 voxel/shape checks per viewer per tick, shared with bounded entity sight checks. |
| `maxGeometryChecksPerTickGlobal` | 262144 | At least the per-viewer limit and at most 16777216; shared globally, including tracker scheduling slots. |
| `maxWorkNanosPerTick` | 5000000 | 100000–50000000 ns; the default is a 5 ms measured-work guard. |
| `maxMaskBytes` | 67108864 | 1024–1073741824 bytes; bounds charged visibility-mask payload, not total JVM heap. |
| `movementDeliveryDeadlineTicks` | 20 | 1–100, at least the refresh interval; missed movement-safe delivery deadlines disconnect the affected viewer. |

One resumable sight job is retained per viewer. Camera, ray, candidate, and shape cursors survive work exhaustion; a later step resumes rather than rescanning the same near blocks indefinitely. Fresh body safety is evaluated independently. Viewer scheduling rotates, and chunk/geometry/lifecycle changes invalidate affected work. A job and its synchronous publication form one pending viewer pipeline; publication does not enqueue another copy of that job.

At range 8, a full visibility snapshot contains at most 6859 cells; at range 16, at most 42875. A smaller configured snapshot budget can therefore reject a range that is otherwise syntactically valid. Temporary snapshots, geometry objects, entity IDs, and collection overhead are separate from `maxMaskBytes`. Mask accounting reserves 1024 bytes per protected section per tracked chunk for delivered and pending bit payloads; ordinary default bounds have eight protected sections.

The runtime also caps announced entity IDs at **16384 per viewer**. This fixed limit is not a configuration field. Saturation fails closed.

The **5 ms guard is not a hard deadline inside capture or one evaluator step**. Work checks between stages and before reveal packets stop subsequent work, but an individual bounded operation can overshoot before returning. Aggregate timings and counters describe instrumented work; they do not prove whole-server tick cost, reveal latency, total memory, or throughput. Client gameplay and representative SMP benchmarks remain required.

## Administration and reload

Commands require vanilla gamemaster command permission. Operator status grants no viewing bypass.

| Command | Current behavior |
| --- | --- |
| `/blindstone status` | Development activation/admission state, versions, effective dimension/bounds, viewers, tracked chunks, backlog, and aggregate failure count. |
| `/blindstone verify` | Separates hook loading, observed packets, rewritten/dropped packets, enforcement, automated-test evidence, and live-test evidence by path. Unobserved or untested paths remain labeled accordingly. |
| `/blindstone inspect <player>` | Restricted viewer summary: tracked chunks, queued plans, visibility-job progress, announced entity count, and bypass state. |
| `/blindstone reload` | Validates the entire file first; publishes only after runtime reconciliation accepts it. Current runtime refuses reload while any viewer session exists. |
| `/blindstone report` | Atomically writes local sanitized diagnostics to `config/blindstone-reports/latest.json`. |

For reload, first ensure no viewer sessions are tracked, then edit the complete file and run `/blindstone reload`. A rejected reload retains the previous effective configuration and generation. Safe online refresh of existing viewers is unfinished, so this restriction is intentional. Reload never opens player admission.

Reports contain configuration/bounds, versions, aggregate timings/counters, typed failure counts, and coverage evidence. They omit player identities, world coordinates other than configured vertical bounds, seeds, raw world data, file paths, and arbitrary exception messages. They stay local; there is no telemetry or automatic updater.

Manual disable and a production activation command are not implemented. Invalid configuration, overload, missing evidence, or filtering failure never automatically switches to unfiltered protected-world delivery. Coherent lighting, complete entity adapters, live gameplay, packet captures, and performance remain release gates.
